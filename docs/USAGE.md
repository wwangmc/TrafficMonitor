# 使用说明

## 启动与日常操作

手机保持越狱与 ElleKit 注入有效，安装 TrafficMonitor，连接 USB 并信任电脑；这套电脑采集器要求已安装的 MKS/roothelp 通道可用。Windows 双击根目录 start.cmd。Python 运行窗口需要保持打开；第一次需要联网安装 tidevice，之后 WebUI 本身无外部 CDN 或云服务依赖。

默认只监控 com.korea.mrtgd2.ios。顶部「监控应用」可搜索名称或 Bundle ID，保存最多 8 项。配置会原子更新手机的精确 Bundle Filter 及各应用自己 tmp/TrafficMonitor/config.plist。新选应用必须完全退出并重新打开；取消选择后，已经运行的旧进程约 1 秒后停止产出新事件，新启动不再注入。不会重启其他应用。

总览切换时间范围后，累计字节、域名/IP 汇总与曲线按窗口查询；速度卡片始终是最近 2 秒的滑动估算。约 1 秒 USB 同步存在显示延迟；不是每秒精确链路计费值。当前应用筛选同时包含有历史记录的应用。

HTTP 列表显示最近 200 条匹配请求；搜索 URL/方法，状态可筛选成功与错误。点击记录可查看完整脱敏 URL、初始/最终 URL、耗时和各类字节字段。未能确定的字段显示「—」，不伪造为 0。下载完成文件不会被监控器读取，无法观察的 body 长度保留未知。

Socket 列表显示最近 200 个描述符/端点会话；其中字节是会话累计值，IP 汇总和顶部累计是所选时间窗口内的增量，口径不同。最近 60 秒出现 I/O 且未关闭/失败视为最近活跃；长期无 I/O 标为闲置。HTTP/2 等多路复用不会拆成多个物理连接，dup 的 fd 别名单独建会话，不能将会话数当作物理连接数。

「历史与存储」可选择 1/3/7 天保留期，最多每类 100,000 条。导出 JSON 包括所选窗口的汇总、曲线，以及最近 200 条匹配请求/会话；不代表完整数据库备份。完整备份请退出服务后复制 desktop/data 目录。清理按钮需确认，会清理数据库记录并 VACUUM/截断 WAL，并同步清理手机自己的四个日志文件；不删除 App 的业务数据，不承诺法证级安全擦除。

## 访问与连接

服务只监听 127.0.0.1，端口默认 27681。直接打开 http://127.0.0.1:27681/ 即可，无需令牌或登录；服务重启后刷新原页面即可继续使用。保留严格 Host/Origin 校验，本机进程可直接调用本地接口。

设备断开或 MKS 无响应时界面显示错误并保留历史。重新连接会重试同步；配置失败会排队重试，不会显示为已在手机生效。MKS 现有服务本身的认证/监听策略由原插件决定；TrafficMonitor 只使用 USB，不新增电脑局域网监听，也不改变原插件的网络设置。

排查顺序：确认手机信任/USB 驱动 → MKS/roothelp 可用 → 选中应用并冷启动 → 查看采集健康报告的丢弃/写入错误。队列压力会丢弃样本，不能据此计算严格完整流量。手机 tmp 文件也可能由系统回收；断线超过日志轮转窗口可能丢历史。

## 卸载

关闭桌面服务；在手机卸载 com.example.trafficmonitor，并完全结束所选应用。手机的 tmp/TrafficMonitor 与电脑 desktop/data 历史独立存在，可先通过界面清理后卸载。不要删除整个应用容器。独立诊断工具位于 Rootless /var/jb/usr/libexec/trafficmonitor/tm-probe，运行 --self-test 会在自己的临时目录写合成测试数据。
